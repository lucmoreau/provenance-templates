This document specifies the two algorithms of the provenance template approach. Instantiation (also called expansion) takes a template and a set of bindings and produces a PROV document in which the variables are replaced by their values. Merge combines several templates, or several documents, into one. The document defines the grouping of variables, the enumeration of their values, the substitution of variables in statements and attributes, the treatment of unbound variables, the identification of statements in a merge, and the error situations.

This is an unofficial draft, part of the PROV-TEMPLATE family of documents [[PROV-TEMPLATE-OVERVIEW]]. It has no official standing of any kind and does not represent the consensus of any standards organisation.

The instantiation algorithm revises section 3 of PROV-TEMPLATE 2014-06-07 [[PROV-TEMPLATE-2014]], edited by Danius Michaelides, Trung Dong Huynh and Luc Moreau; its examples are kept, with the output ProvToolbox [[PROVTOOLBOX]] produces for them today. The algorithms are described as ProvToolbox implements them (branch development2_0, 2026-10-16); editor's notes mark where the implementation departs from [[PROV-TEMPLATE]], or where a decision is pending.

The artefacts on which these algorithms operate — templates, variables, bindings, the tmpl: vocabulary — are defined in [[PROV-TEMPLATE]]. A template processor conforms to this specification if, for every template and set of bindings, its instantiation produces the document specified here, up to the generated identifiers of and the order of statements, and if it signals the error situations of .

Introduction

Instantiation processes each statement of a template in turn. The group variables of a statement — the variables in its identifier and argument positions — determine how many times it is instantiated: once for each combination of their values. Variables that are linked change value together, and form a group; distinct groups combine as a Cartesian product. The attribute variables of a statement — the variables in its attributes — take, for each instance of the statement, the next entry of their values. Unbound variables leave positions empty, drop attributes, or drop statements. Merge, finally, identifies the statements of several documents that describe the same thing.

The following example, from [[PROV-TEMPLATE-2014]], is used throughout.


      

    


    

      
Preliminaries


      

        
Positions of a statement

        

          The positional slots of a statement are its identifier and its positional arguments up to, and
          excluding, its time, in the order of PROV-N [[PROV-N]]. The table gives their number, identifier
          included.
        

        

          
StatementPositional slots

          
            
entity, activity, agent1: id

            
used, wasGeneratedBy, wasInvalidatedBy3: id, activity or entity, entity or activity

            
wasStartedBy, wasEndedBy4: id, activity, trigger, starter or ender

            
wasAssociatedWith4: id, activity, agent, plan

            
wasDerivedFrom6: id, generated entity, used entity, activity, generation, usage

            
wasAttributedTo, actedOnBehalfOf, wasInformedBy, wasInfluencedBy, specializationOf, alternateOf, hadMemberthe identifier and the arguments of the relation

          
        

        

          The free variables of a statement are the variables in its positional slots. Its
          attribute variables are the variables that are values of its attributes, or names of its
          attributes, except the values of tmpl:linked.
        

      


      

        
Values of a variable

        

          Given a set of bindings B, values(B, v) denotes the sequence bound to variable v: for a group
          variable, a sequence of qualified names; for an attribute variable, a sequence of entries, each a sequence of
          values (a single value counts as a sequence of one). A variable absent from B, bound to null
          or to an empty sequence, is unbound. The values of a vargen: variable are given by the
          member vargen of the bindings [[PROV-TEMPLATE]].
        

      

    


    

      
Instantiation

      

        The instantiation of a template T with a set of bindings B is a PROV document with a single bundle. Only the
        first bundle of T is considered; if T has none, it is an error (BundleMissing). Its namespace
        declarations are those of the bundle of T, and of the context of B for the prefixes the values use.
      

      
Document instantiate(Template T, Bindings B) {
  b      = the first bundle of T                       // BundleMissing if none
  G      = grouping(b, B)                              // section 4.1
  out    = empty sequence of statements
  for each statement s of b, in order {
    u     = groupUsage(s, G, B)                        // section 4.2
    count = 0
    for each index i of u, in index order {            // section 4.3
      env  = environment(u, i, B)
      s2   = substitutePositions(s, env)               // section 4.4
      s3   = expandAttributes(s2, B, env, count)       // section 4.5
      if (keep(s3)) {                                  // section 4.6
        if (order requested) add tmpl:order = "i" to s3
        append s3 to out
      }
      count = count + 1
    }
  }
  id = bundleIdentifier(b, B)                          // section 4.7
  return a document with one bundle, identified by id, containing out
}


      

        
Grouping of variables

        

          A group is a set of group variables that change value in step. The
          grouping of a bundle is a partition of its group variables into groups, each identified by a
          natural number. It is computed deterministically as follows.
        

        
Grouping grouping(Bundle b, Bindings B) {
  V      = the free variables of all statements of b, sorted by IRI
  linked = for each statement s of b with identifier v1 and an attribute tmpl:linked = v2:
             v1 is linked to v2, and v2 to v1
           for each member v1: v2 of B.linked:
             var:v1 is linked to var:v2, and var:v2 to var:v1
  linked = the transitive closure of linked
  g = empty grouping; n = 0
  for each v in V {
    if v belongs to no group of g {
      add {v} ∪ linked(v) to g, as group n
      n = n + 1
    }
  }
  return g
}

        

          In the absence of links, each variable is a group of its own. In the example, var:a is group
          0 and var:b group 1. With agent(var:a, [tmpl:linked = 'var:b']), the two
          variables form group 0.
        

        

          [[PROV-TEMPLATE-2014]] incremented the group counter for every variable, whether or not it started a new
          group; ProvToolbox numbers the groups consecutively. The numbers only matter for tmpl:order.
        

      


      

        
Group usage

        

          The group usage of a statement s is the list, in ascending order, of the groups of its free
          variables that are bound, or that are vargen: variables. Each group g of the usage has a
          length: the number of values of its first variable, or 1 for an unbound vargen:
          variable. All the variables of a group MUST be bound to the same number of values
          (IncorrectNumberOfBindingsForGroupVariable).
        

        

          A group whose variables are unbound var: variables is not part of the usage: it does not
          multiply the statement, and its variables are treated as unbound when the statement is instantiated.
        

        

          In the example, the usage of agent(var:a) is [0], of entity(var:b) [1], and of
          wasAttributedTo(var:b, var:a, …) [0, 1], with lengths 2 and 3.
        

      


      

        
Enumeration of values

        

          For a group usage [g1, …, gn], an index is a list
          [i1, …, in] with 0 ≤ ik < length(gk). The indices are
          enumerated in index order, in which i1 is the least significant: [0, 0], [1, 0],
          [0, 1], [1, 1], … A statement whose usage is empty has exactly one index, the empty list [], and is
          instantiated once. The number of indices is the product of the lengths: the statement is instantiated for
          each combination of the values of its groups, while the variables of one group change value in step.
        

        

          The environment of an index maps each variable v of each group gk to
          values(B, v)[ik]. Only qualified names enter the environment: a group variable
          bound to a literal is treated as unbound.
        

        

          The count of an index is its rank in the enumeration, from 0. It selects the entry of each
          attribute variable.
        

      


      

        
Substitution in positional slots

        
Each positional slot of the statement is rewritten:

        
    
          
  • a qualified name that is not a variable is kept;
    • 
          
  • a variable in the environment is replaced by its value;
    • 
          
  • a vargen: variable not in the environment is replaced by its generated value ();
    • 
          
  • an unbound var: variable is replaced by nothing: the slot is empty, written -
            in PROV-N. A processor MAY offer to preserve unbound variables instead, so that a template can be
            instantiated in several steps.
    • 
        

        

          
Generated values

          

            An unbound vargen: variable is given a fresh qualified name in the namespace
            urn:uuid:, with prefix uuid, whose local part is a random UUID [[RFC9562]].
            The value is generated once per instantiation, and used for every occurrence of the variable in it. A
            vargen: variable bound to more than one value is an error
            (BundleVariableHasMultipleValues).
          

        

      


      

        
Expansion of attributes

        

          The attributes of the statement are rewritten for the current count c. An attribute whose value is not a
          variable is kept. For an attribute whose value is an attribute variable v:
        

        
    
          
  • if v is unbound, the attribute is dropped;
    • 
          
  • otherwise, let e be the entry values(B, v)[c]; the attribute is replaced by one attribute
            per value of e, with the same name. A value that is a qualified name is written as such; a literal is
            written with its type.
    • 
        

        

          An attribute whose name is a variable p and whose value is a variable v is replaced, for each k, by an
          attribute whose name is the k-th qualified name of values(B, p)[c] and whose value is the k-th
          value of values(B, v)[c]. The two entries MUST have the same length.
        

        
The tmpl: attributes are then consumed:

        

          
AttributeEffect

          
            
tmpl:labelone prov:label per value of the entry. If the value is a variable, tmpl:label is kept with that variable as value (the template-generating case).

            
tmpl:timesets the time of a usage, generation, invalidation, start or end; dropped on other statements.

            
tmpl:startTime, tmpl:endTimeset the start or end time of an activity; dropped on other statements.

            
tmpl:IDif the value is a qualified name and the statement has no identifier, becomes its identifier.

            
tmpl:linkeddropped; it was used by the grouping.

            
tmpl:if, tmpl:notifsee .

          
        

        

          If an attribute variable has fewer entries than its statement has instances, it is an error
          (IncorrectNumberOfBindingsForStatementVariable).

Statements kept and left out

        

          An instantiated statement is kept or left out according to its kind and to which of its slots are
          empty after substitution:
        

        

          
StatementLeft out when

          
            
entity, activity, agentits identifier is empty

            
wasAssociatedWithits agent is empty

            
wasAttributedToits agent is empty

            
actedOnBehalfOfits delegate or its responsible is empty

            
other relationsnever: they are kept, with their empty slots

          
        

        

          A processor MAY offer a stricter mode, in which a statement is kept only if all its variables are bound
          (ProvToolbox's -allexpanded).
        

        

          A statement carrying tmpl:if is left out if the variable is unbound; a statement carrying
          tmpl:notif is left out if the variable is bound [[PROV-TEMPLATE]].
        

        

        

        

          The instantiation above contains used(ex:writing,-,-),
          wasDerivedFrom(ex:report, -) and wasInformedBy(ex:writing,-), which are not
          valid PROV: their second argument is mandatory [[PROV-N]]. [[PROV-TEMPLATE-2014]] made an unbound
          var: variable in a mandatory position an error, UnboundMandatoryVariable. Either
          that error is restored, or such relations are left out, like nodes without identifier.
        

        

          
    
            
  • ProvToolbox's interpreter does not implement tmpl:if and tmpl:notif.
    • 
            
  • It always leaves out wasInfluencedBy, mentionOf and the dictionary
              relations.
    • 
            
  • It does not support hadMember with more than one member.
    • 
          

        

      


      

        
Bundle identifier

        

          The identifier of the instantiated bundle is the identifier of the template's bundle, if it is not a
          variable. If it is a var: variable, it MUST be bound to exactly one value
          (BundleVariableHasNoValue, BundleVariableHasMultipleValues). If it is a
          vargen: variable, it is its bound value, or a generated one.
        

      


      

        
The order attribute

        

          When requested, each instantiated statement is given the attribute tmpl:order, whose value is
          the string of its index, such as "[1, 0]", or "[]" for a statement without
          group. It records which combination of values produced the statement.
        

      

    


    

      
Merge

      

        The merge of a sequence of documents d1, …, dn — templates, or
        instantiated documents — is a document that contains the statements of all of them, in which the
        statements that describe the same thing are identified. Merge does not rename variables: since variables
        are qualified names, a variable that occurs in two templates denotes the same node in both, and merging
        templates composes them.
      

      
Document merge(Document d1, ..., Document dn) {
  m = empty document
  for k = 1 to n: m = mergeInto(m, dk)
  return m
}

      
Statements are identified as follows.

      
    
        
  • 
          Entities, activities and agents with the same identifier are one: their attributes are the union of
          their attributes. An activity's start and end times, and an entity's value, are taken from the first
          statement that has them.
        
    • 
        
  • 
          Relations with an identifier are one if they have the same identifier and the same arguments; their
          attributes are united. Relations with the same identifier and different arguments are kept apart.
        
    • 
        
  • 
          Relations without identifier are one if they are equal, attributes included: relations that differ by
          their attributes are kept apart.
        
    • 
        
  • 
          Bundles with the same identifier are one, and their statements are merged recursively. A processor MAY
          offer to flatten the result, merging the statements of all bundles into a document without
          bundle.
        
    • 
      

      

        The output lists entities, then activities, then agents, then relations by kind. In a template
        transformation file [[PROV-TEMPLATE]], a merge task merges its inputs in the order given.
      

      

        

        

      

      

      

        ProvToolbox cannot merge mentionOf and the dictionary relations, and does not write anonymous
        qualified memberships or identified alternateOf relations in the merged document. A merge task
        with a single input writes no output.
      

    


    

      
Errors

      
A template processor MUST signal the following error situations.

      

        
ErrorSituation

        
          
BundleMissingThe template has no bundle.

          
BundleVariableHasNoValueThe bundle identifier is an unbound var: variable.

          
BundleVariableHasMultipleValuesThe bundle identifier, or a vargen: variable, is bound to more than one value.

          
IncorrectNumberOfBindingsForGroupVariableThe variables of a group are bound to sequences of different lengths [[PROV-TEMPLATE-2014]].

          
IncorrectNumberOfBindingsForStatementVariableAn attribute variable has fewer entries than its statement has instances [[PROV-TEMPLATE-2014]].

          
MissingAttributeValueAn entry of an attribute variable is null.

          
UnsupportedValueTypeA literal has a type the processor does not support.

        
      

      
A template processor SHOULD warn about variables of the template left unbound, and about variables of the bindings that the template does not use.

      

        
How ProvToolbox currently signals these situations:

        
    
          
  • BundleMissing is an UncheckedException, "Bundle missing in template".
    • 
          
  • Unequal lengths in a group fail with an index out of bounds when a later variable is shorter, and are
            silently truncated when it is longer.
    • 
          
  • Too few entries for an attribute variable reuse the first one, with a warning.
    • 
          
  • Literal types other than xsd:string, xsd:int and xsd:boolean on
            ordinary attributes raise IllegalArgumentException.
    • 
          
  • The warning about unused bindings removes the used variables from the caller's bindings.
    •
