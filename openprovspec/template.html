Provenance Template Ontology

In this section, we provide details about OpenProv Ontology ... .

The vocabulary is identified by http://openprovenance.org/ns/tmpl#; its terms are in the namespace http://openprovenance.org/ns/tmpl#, prefix tmpl. The reserved attributes of provenance templates. A template is a PROV document whose placeholders are variables, qualified names in the var namespace (http://openprovenance.org/var#), or in the vargen namespace (http://openprovenance.org/vargen#) for identifiers the instantiation generates when the bindings leave them unbound. A variable can stand where PROV admits a qualified name: an identifier, an attribute, a value. Where PROV constrains the syntax of a value — a label is a string, a time an xsd:dateTime — a template writes a tmpl attribute paired with a variable instead, and the instantiation writes the PROV attribute; further tmpl attributes make a statement conditional, give a relation an identifier, or tie the expansion of two statements together. Every tmpl attribute is consumed by the instantiation: none survives into an instantiated document.

Each term is declared as rdf:Property: an attribute a template pairs with a variable, and which the instantiation consumes.

Syntax-constrained attributes

Paired with a variable in the template; the instantiation writes the PROV attribute — prov:label, prov:time, prov:startTime, prov:endTime — with the bound value in its place, since PROV admits no qualified name there.

rdfs:commentInstantiates prov:label on the statement: the variable's bound string, or one prov:label per string when the variable is bound to several.

Conditional instantiation

Whether the statement is instantiated at all depends on the variable being bound.

tmpl:ifhttp://openprovenance.org/ns/tmpl#if
rdfs:labelif
rdfs:commentThe statement is instantiated only if the variable is bound; unbound, the statement is left out of the instantiated document. A variable bound to a sequence of values counts as bound.
tmpl:notifhttp://openprovenance.org/ns/tmpl#notif
rdfs:labelnot if
rdfs:commentThe statement is instantiated only if the variable is not bound; bound, to a value or to a sequence, the statement is left out. The complement of tmpl:if.

Identifiers and expansion

An identifier for a relation written without one, and the pairing of variables that expand in step.

tmpl:IDhttp://openprovenance.org/ns/tmpl#ID
rdfs:labelidentifier
rdfs:commentOn a relation written without an identifier: the variable's bound qualified name becomes the relation's identifier, so that instantiations of the same relation can be told apart and referred to. Ignored when the value is not a qualified name, when the relation already has an identifier, or on a node.
rdfs:domainprov:Influence
rdfs:rangexsd:anyURI
tmpl:linkedhttp://openprovenance.org/ns/tmpl#linked
rdfs:labellinked
rdfs:commentOn a statement whose identifier is a variable: names another variable whose expansion this statement follows. Variables bound to sequences of values expand a statement once per value; two variables linked, directly or through a chain of tmpl:linked, expand in step, the i-th value of one with the i-th value of the other, rather than as a product. The link is symmetric, and may also be declared in the bindings. Not a free variable of the statement: it binds nothing itself.
