• Name: EntityInit
  • Fully Qualified Name: org.openprovenance.templates.physical.EntityInit
  • IRI: https://openprovenance.org/templates/org/openprovenance/templates/physical/EntityInit
  • Purpose: This template describes how an entity is initially created.
  • Context: The template describes a registration activity that results in a generated entity and an optional specialization.
  • Design considerations: The template allows new attributes for the entity and its specialization to be defined after registration; in particular, a specific location can be specified for the specialization.
  • Automation: ttfs/config-entity-init.json

  • Details:

    The template does not assume the existence of any entity or agent. It allows a new entity to be defined without specifying its provenance, thereby enabling the “bootstrapping” of provenance. It is the counterpart, for entities, of the template AgentInit.

    A registration activity activity generates an entity and its specialization entity0. Placeholders are provided for the type and eprops attributes of entity. It is also possible to specify a location and other attributes eprops0 for entity0.

    The intent is that the type and eprops attributes are inherited by all specializations entity0, whereas location and eprops0 may change as specializations evolve (using Triangle2-Entity-SDS).

    A PROV entity has fixed aspects, encoded as attribute-value pairs, which hold throughout its lifetime; once one of them changes, there is a new entity, derived from the previous one. We cannot claim (or enforce) that an entity’s location does not change during its lifetime. Therefore, we adopt the attribute ‘last known location’, abbreviated phys:lkl, to record an entity’s location. If the entity changes location without being observed, its last known location remains unchanged. A new observation of the location must result in another entity with the latest location.

    The activity is annotated with the type phys:RegisteringEntity to provide an unambiguous way to recognise this template by its activity type; this type can then be used in queries.
